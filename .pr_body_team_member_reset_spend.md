## Screenshots / Proof of Fix

Run a local proxy:

```
python litellm/proxy/proxy_cli.py --config litellm/proxy/dev_config.yaml --detailed_debug --reload --use_v2_migration_resolver 2>&1 | tee litellm.log
```

1. Open http://localhost:4000/ui/?page=teams, open a team, go to the Members tab, and give a member a small weekly team-member budget (Edit member; set Team Member Budget to 0.01 and budget duration 7d).
2. Make real LLM calls with a key scoped to that user and team until the member's Current Cycle Spend on the Members tab is non-zero.
3. Reset that member's current-cycle spend directly against the live proxy (replace the ids):

```
curl -sS -X POST http://localhost:4000/team/member_reset_spend \
  -H "Authorization: Bearer $LITELLM_MASTER_KEY" \
  -H "Content-Type: application/json" \
  -d '{"team_id":"<team_id>","user_id":"<user_id>","reset_to":0}'
```

Expected response shows the new spend at 0 and the prior value preserved:

```
{"team_id":"<team_id>","user_id":"<user_id>","spend":0.0,"previous_spend":<old>,"max_budget":0.01,"budget_reset_at":null}
```

4. Reload the Members tab and confirm Current Cycle Spend is now $0 while Total Spend is unchanged. Then exercise the button itself: on the member row click the reset (circular arrow) action, confirm in the modal, and watch the spend drop to $0.

## Changes

LiteLLM can give each user a per-team budget that is tracked on `LiteLLM_TeamMembership.spend` and enforced against a linked budget with a duration like `7d`. Keys already have a manual override through the "Reset Spend" button backed by `POST /key/{key}/reset_spend`, but there was no equivalent for a team member's spend, so an admin's only options when a member exhausted their weekly budget were to wait for the window to roll over or raise the budget.

This adds `POST /team/member_reset_spend`, guarded by the same proxy, team, or org admin check that `/team/member_update` uses. It zeroes only the current-cycle `spend` and leaves lifetime `total_spend` untouched, then invalidates the same spend-counter and management-cache keys that the automatic `ResetBudgetJob` uses so the reset takes effect immediately across pods. `reset_to` defaults to 0 and is validated to be non-negative and no greater than the member's current spend.

On the dashboard a reset action is added to the team Members table, gated to proxy and team admins, with a confirmation modal that makes clear lifetime total spend and the spend history in logs are preserved. The shared `MemberTable` gains opt-in `onResetSpend` props so the organization members view that also uses it is unaffected.
